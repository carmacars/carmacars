neighbourhood of every city in North America; every category and its synonyms; every stat of every car; and (later the

Production numbers are read-only counts from October 23 (Management API, 2.5 s statement timeout). The data sources
(vPIC, fueleconomy.gov, NRCan, Wikidata, Geofabrik, GeoNames) could not be reached from the development sandbox (the

What is missing:

- **Before 1981**: nothing (the catalog starts at vPIC's first year).
- **Trims**: 96% of models have none. EPA has no trim field; the vPIC API has no trim list. The vPIC standalone database
  carries trim names in its VIN patterns.
- **Canadian-market models** EPA never rated (for example the Chevrolet Orlando): missing. NRCan's Fuel Consumption
  Ratings list them from 1995.
- **Mexican-market models** (Nissan March and Tsuru, Chevrolet Aveo and Beat, VW Vento): missing. The only free source
  found is INECC/CONUEE's Ecovehiculos data on datos.gob.mx (Libre Uso MX licence). Not implemented: its format could
  not be checked from here. Follow-up.
- **Heavy trucks (class 3 to 8), buses, motorcycles, low-volume makes**: missing (EPA does not rate them). vPIC knows
  them.

Sources and licences checked: NHTSA vPIC and its standalone database (US government work, public domain); EPA
fueleconomy.gov (public domain); NRCan Fuel Consumption Ratings (Open Government Licence - Canada: free use with
attribution, which the page now gives); Wikidata (CC0); Transport Canada recalls (Open Government Licence - Canada, a
possible follow-up); NHTSA NCAP safety ratings API (public domain, a possible follow-up).

### Figures on every vehicle page (d)

Shown when a source has them: L/100 km city, highway and combined (MPG US and imperial converted), kWh/100 km, electric
range, CO2 g/km, engine (displacement, cylinders, turbo or supercharger), drive, gearbox, fuel, EPA's annual fuel cost,
240 V charge time, luggage volume, battery kWh (EPA); length, width, height, wheelbase, curb weight by body (vPIC
Canadian specifications); recalls and complaint counts (NHTSA); seats only from a car of ours. Power, torque, 0 to 100
km/h, top speed, fuel tank and towing are left out: no free source publishes them for every car.

Free figures not shown yet: seats, doors, GVWR and engine horsepower from the vPIC database's patterns (the export
query can add those columns); NRCan's CO2 and smog ratings (the import reads the files; storing the two ratings needs a
column); NCAP star ratings.

## 2. What this branch adds

- `0115`: the 21 own terms and 97 synonyms; catalog years from 1900; `program_settings.vpage_extra_sources` (empty by
  default); the priority sitemap store, the place directory store and the make index (section 4).
- Catalog import (`web/scripts/catalog/import.mjs`, `normalise.ts`), off unless asked:
  - `--vpic-export <tsv>`: the vPIC standalone database exported by `web/scripts/catalog/vpic-export.sql` (make, model,
    year, vehicle type, trim). New makes allowed (`--vpic-export-known-makes` to refuse them); types car, mpv, truck by
    default (`--vpic-export-types car,mpv,truck,motorcycle,bus,lsv`). Trims become trim lines where the curated list
    has none for that year (40 names a line at most).
  - `--nrcan download|<csv,...>`: NRCan ratings, matched to the catalog's models (a name's first words: "Sierra 4WD AT4"
    is the Sierra); Canadian figures only on a model year EPA has none for, marked `src: 'nrcan'` and attributed on the
    page. No new makes.
  - `--wikidata download|<json>`: car models first produced before 1981 (one model year a production year, 20 at
    most), known makes only unless `--wikidata-new-makes`.
  - The catalog workflow restores vPIC's backup in a SQL Server container, exports it, and passes the sources that
    `vpage_extra_sources` (or a manual run's `extra`) names. Every import replaces the whole catalog: **once a source is
    on, keep it on**, or its pages disappear.
- Places: OpenStreetMap neighbourhoods, suburbs, quarters and boroughs mapped as areas (ways and multipolygon
  relations), placed at their middle, with ids of their own (`-(2*10^12 + way id)`, `-(3*10^12 + relation id)`); a node
  and an area with the same name close by stay one place. Workflow input `osm_areas` (on by default; the workflow runs
  only when started by hand).
- /buy synonyms served (they were 404); synonym pages now name their canonical.

## 4. Crawl priority and click depth (the owner's second request)

- **`/sitemap-priority.xml`, first in `/sitemap.xml`** (at most 50,000 addresses): every car page of the fleet and the
  landing pages (from `sitemap_all`), every make page, the popular models (`vehicle_catalog_popular`, 149) with their
  years and trims from `vpage_popular_from_year` (2015) as the stored vehicle sitemap lists them (indexed pages only),
  then the Ontario cities and neighbourhoods nearest our location for the first 12 rental, 3 buying, 4 detailing and 4
  body shop terms (23 terms; synonyms never). Stored by a job every 30 minutes (`app.sitemap_priority_refresh`, pg_cron
  `carmacars-sitemap-priority`), so the file is one read. lastmod: the vehicle page's stored date, the place's own date,
  the car's own date; nothing else.
- **Click depth** (home, footer Browse, then plain `<a href>` links): `/places` lists the directory's pages, `/places/<n>`
  lists a thousand places by id (a primary key range: one cheap read), each place page now links to every own term's
  page for that place. So: any place page **3 clicks**, any place and term page **4**. `/makes` lists every make with
  every model: model **2**, year **3** (the model page lists its years), trim **4** (the year page lists its trims). Still
  deeper than 4: the trim in a place (5), in a place and a colour (6), and the term trees `/t/<term>/...` (they hang off
  the term pages; reaching every one within 4 would need a link list per trim of every place).
- Breadcrumbs with BreadcrumbList JSON-LD were already on every hub and vehicle page; "nearby places" (8) and "similar
  models" blocks were already on the leaf pages.
- **Structured data**: hub pages keep BreadcrumbList, FAQPage (questions answered from the page's own data), ItemList
  of the real cars and Service for detailing and body shop; a rental page now carries a Service (car rental, our
  business as provider) only for a place within the delivery reach. Vehicle pages keep Product/Car with the sourced
  specs and offers only for real cars. Ratings appear only from real published reviews (the business above
  `seo_rating_min_reviews`, a car's own reviews). Nothing invented.

## 5. Thin pages, for the owner to decide

Defaults are unchanged: every page indexed (`place_quality_gate` off, `vpage_index_mode` 'all'). Thinnest first:

1. **Place and term pages far beyond the delivery reach** (about 99% of the 475,802 places: the United States, Mexico,
   most of Canada): the copy honestly says we serve the Toronto area; the unique facts are the distance and the nearest
   airport. The quality gate (Admin > Settings > Search) indexes only places within the reach and rental terms with a
   real matching car.
2. **Hamlets and small neighbourhoods** with no landmark and no airport nearby: name, distance, the same cars.
3. **A trim in a place and a colour** (trims x places x 12 colours): templated; the rules mode
   (`vpage_index_mode = 'rules'`) indexes only trims with our car or popular models.
4. **Model years with no figures** (5,621 now, vPIC only; many more after vpicdb): name, years, recalls at best.
5. **The term trees** (`/t/<term>/...`, one per own term): the vehicle page again with a term's block.
6. Synonym pages: already noindex with the canonical.

## 6. Running the imports, after the database moves

1. Deploy the branch (migrations through 0115). The migration fills the priority and directory stores once; pg_cron
   keeps them.
2. Set the caps for the new disk (Admin > Settings, or SQL): `update program_settings set place_db_cap_mb = <80% of disk
   in MB>, vpage_import_db_cap_mb = <same>;`
3. Finish the places, gently (2,000 places a transaction, paused when the database is busy):
   `gh workflow run places.yml -f regions=MX-NAY,MX-NLE,MX-OAX,MX-PUE,MX-QUE,MX-ROO,MX-SLP,MX-SIN,MX-SON,MX-TAB,MX-TAM,MX-TLA,MX-VER,MX-YUC,MX-ZAC -f osm=true -f osm_areas=true -f environment=production`
   then, for the areas everywhere and the finish step (GTA flags, province parents, landing links):
   `gh workflow run places.yml -f regions=all -f osm=true -f osm_areas=true -f environment=production`
   Check: `select country, kind, count(*) from places group by 1, 2;` and `select count(*) from places where flags & 1 <> 0;`
   (the GTA, expected in the thousands).
4. Catalog dry run with the further sources (nothing written):
   `gh workflow run catalog.yml -f write=false -f extra=vpicdb,nrcan,wikidata`
   Read the annotations: `by_vpicdb`, `by_nrcan`, `by_wikidata` (new makes, models, model years), `extra.nrcan.files`
   (each NRCan file's rows or why it was skipped), `projected_bytes`. If the vPIC export step failed, its annotation says
   why (the backup link on vpic.nhtsa.dot.gov/api or the restore); the query in `vpic-export.sql` was written from vPIC's
   documented schema and has not been run here.
5. Switch the sources on and import:
   `update program_settings set vpage_extra_sources = '{vpicdb,nrcan,wikidata}';`
   `gh workflow run catalog.yml -f write=true` (or wait for the monthly run). Leave them on from then.
6. The stores refresh by themselves (vehicle sitemaps every 30 minutes, then the priority file); submit `sitemap.xml`
   in Search Console as before.
