# 01. Public site

Owner: workstream B. Routes under `src/app/(public)/`. Everyone can open every route in this file. All pages are static and cached (`00-overview.md` section 2.4). SEO rules for these pages (titles, structured data, canonicals) are in `14-seo.md`; this file covers layout, components and behaviour.

## 2. Look, photos and scroll effects

The site is photo-led: black, white and red, large type, full-bleed photos on one consistent backdrop.

**Prototype.** A static prototype of the public pages exists in `prototype/` (home, fleet, car pages, request, confirmation, delivery, requirements, owners, how it works, FAQ, contact, sign-in, policies, 404, a style guide). It is the visual reference for layout, type and components. Its pages map to the routes in section 4: `index` to `/`, `fleet` to `/cars`, `car-*` to `/cars/[slug]`, `request` to `/book/[slug]`, `confirmation` to `/book/sent/[bookingNumber]`, `delivery` to the city, neighbourhood and airport pages (and the delivery section of each car page), `requirements` to `/car-rental/under-25`, `/car-rental/g2-licence` and the Requirements block, `owners` to `/list-your-car`, `cancellation` to `/cancellation-policy`. Where the prototype and this file differ on behaviour or data, this file wins; where they differ on appearance, the prototype wins.

| Effect | Where | How | Limits |
| --- | --- | --- | --- |
| Hero parallax | Home hero, car page hero | The photo moves at 0.85 of scroll speed using CSS `animation-timeline: scroll()`; a static image where the browser lacks support | Transform only; never on text |
| Reveal on enter | Section headings, cards, fee rows | Opacity 0 to 1 and 16 px rise over 400 ms with `animation-timeline: view()`; an `IntersectionObserver` fallback adds a class | Each element animates once |
| Pinned gallery | Car page, desktop only | The gallery column is `position: sticky` while the details column scrolls | Phone uses a swipe carousel instead |
| Horizontal snap rail | "Popular cars", "Nearby locations" | CSS scroll snap, arrow buttons on desktop | No auto-advance |
| Header change | All pages | Transparent over the hero, solid black after 80 px | |
| Number count-up | Home trust band (cars, reviews, cities) | Counts up once when visible | Real numbers from the database at build; hidden if a number is under its minimum (for example fewer than 10 reviews) |

Rules: no scroll hijacking, no video autoplay with sound, no animation longer than 600 ms, nothing animates under `prefers-reduced-motion: reduce`, and the largest image on each page is never lazy-loaded or animated in (it is the LCP element).

**Image component.** `<CarImage>` renders `<picture>` with AVIF and WebP sources at 480, 800, 1200, 1600 and 2400 px wide, pre-generated by the listing pipeline and served from the `vehicle-public` bucket's own domain (`NEXT_PUBLIC_VEHICLE_PHOTOS_URL`). Width and height are always set. The hero uses `fetchpriority="high"`. No runtime image transformation runs in the Worker.

### 4.3 `/cars/[slug]` Car page

The most important page on the site. One per published vehicle. Content rules that keep it unique are in `14-seo.md` section 4.

| Item | Detail |
| --- | --- |
| Purpose | Show the car completely, show when it is free, show the real price, start a request |
| P layout | Swipe gallery (cover first, counter "1 / 14"); title (year make model trim); class, seats, transmission, fuel chips; rating link; price line ("from $X a day"); availability calendar (one month, swipe for next); date fields and live `PriceBreakdown`; description; features list; what is included; requirements; fees table (collapsed); pickup and delivery; reviews; FAQ; similar cars rail. Sticky bottom bar: total or "from" price and "Request to book" |
| D layout | Two columns. Left (58%): sticky gallery grid (cover large, four small, "See all photos" opens a lightbox), then description, features, included, requirements, fees, pickup and delivery, reviews, FAQ. Right (42%): sticky booking panel with dates, calendar (two months), `PriceBreakdown`, "Request to book", and the line "No card needed to request. We confirm and send you an offer." |
| Static data | `public_vehicle_listings` row, `public_vehicle_photos`, reviews, fee catalogue |
| Live data (browser) | `app.public_vehicle_calendar()` for the next 6 months; `app.quote_booking(vehicle, from, to, options)` on every date or option change (debounced 300 ms) |

**Booking panel fields**

| Label | Type | Validation | Default | Stored |
| --- | --- | --- | --- | --- |
| Pickup date and time | date-time, 30-minute steps | Required. At least 2 hours from now. Not inside an unavailable range | From the query string, else empty | Carried to `/book/[slug]`; then `bookings.pickup_at` |
| Return date and time | date-time | After pickup. At most 30 days after pickup. Range must not cross an unavailable range | From the query string | `bookings.return_at` |
| Delivery | toggle | Shown only when the car's `delivery_fee_cents` is above 0 | Off | `bookings.pickup_method` |
| Return pickup | toggle | Same for `pickup_fee_cents` | Off | `bookings.return_method` |
| Non-refundable rate (save 10%) | toggle | None | Off | `bookings.booking_type` |

`PriceBreakdown` shows exactly what the function returns: days and rate applied ("3 days: 1 daily, 2 weekend"), rental charge, discount if chosen, delivery and pickup, HST, **total due at booking**, then separately "Refundable deposit at pickup: $X" and "Kilometres included: N (then $0.35 per km)". Age-based fees and extras are added in the wizard, and the panel says so: "Driver age and extras are added on the next step."

**Calendar.** Unavailable days are struck through and not selectable. A day that is partly taken (a return at 10:00) is shown half-filled and can be the start or end of a range. Tapping a start then an end selects the range. Nothing shows who has the car or why it is unavailable.

### 4.10 `/unsubscribe/[token]`, `/r/[code]`, `/go/[token]`

| Route | Behaviour |
| --- | --- |
| `/unsubscribe/[token]` | Shows "You are unsubscribed from CarmaCars offers." immediately on load for a valid token (the email's List-Unsubscribe header posts to the same handler). Action `unsubscribe(token)`: sets `users.marketing_unsubscribed_at`, sets `consents.withdrawn_at` for the marketing consent, inserts `email_suppressions` **[new]**. | `/r/[code]` | Looks up the code in `owners.referral_code` and `staff_profiles.referral_code`. Stores it in a first-party cookie for 30 days and redirects to `/cars`. The request wizard reads it into `bookings.referred_by_code`. Unknown code: redirect without storing |
| `/go/[token]` | A signed, single-purpose link from an email (view offer, upload documents, pay, leave a review). Valid tokens sign the user in for that one destination; expired tokens go to `/sign-in` with the destination preserved. Tokens are stored hashed in `action_links` **[new]** with purpose, user, booking, expiry and `used_at` |
