# Security audit: Release 48, before deploy (November 2026)

Branch `r48-sec` from `r48-int` (51753869). Migration `3400_r48sec_hardening.sql`. Tests: `supabase/tests/99_r48sec_security.sql`,
`web/src/lib/security/client-ip.test.ts`, `web/src/features/mobile-api/revoke.test.ts`, `web/src/features/forms/email.test.ts`,
`web/src/integrations/vision/fallback.test.ts`, `web/src/lib/auth/session.test.ts` (issuer), `web/tests/e2e/mobile-api.spec.ts` (sign-out).

Scope: everything new in R48 (`git log origin/main..origin/r48-int`, 132 commits): the native app API `/api/m/v1` (66 routes) and
passkeys (3170); fees, evidence and the dispute kit; owner-use billing and the late fee; rewards and referral credits; the
tracker ingest; the live map's people layer; the pickup identity check; the terms pop-up; SEO lead capture and `cc_src`;
`portal-gate.ts`; the visitor-signals job. Checked against the 20-item checklist (security-checklist-reel), the release
checklist and the patterns the brand audits found.

## Checked and fine

- **IDOR, every `/api/m/v1` route.** Handlers add no rule of their own: each runs the website's server action or read as the token's
  person (`asMobileCall`), so the database's checks apply. Trips resolve through `my_booking` (auth.uid()); return links only for the
  booking's renter (`server_return_link` with the user); field jobs through `field_read job`; leads and offers through the door with
  the Sales/CS gate and two-step; owner routes through `app.portal_owner_id`; passkeys by `(id, user_id)`; notification preferences
  are the person's own. Self check-in photos must be `condition-photos/bookings/<this booking>/self-pickup/<uuid>.jpg|png`.
- **Bearer tokens (checklist 8).** ES256/RS256 only (no `none`, no HS swap), key by `kid` from the project's JWKS read at run time
  (10 minutes), `exp`, `aud`, `role`, `sub`, now `iss`. No cookie is read inside a mobile call, so the API cannot be driven from
  another site (CSRF). The app keeps tokens in the keychain (`AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`).
- **Passkeys.** Challenges are random (two `gen_random_uuid`), five minutes, single use, spent in the same statement that checks them;
  origin, type, rpIdHash, user presence and verification, signature over authenticator data and client data hash; the counter must
  move forward; 30 challenges in five minutes per address or person; RLS on, service role only. A passkey session is aal1, so staff
  still need the second factor.
- **Fees, evidence, dispute kit, owner-use billing, late fee.** Lines lock the booking and the rows they bill (`for update`, `skip
  locked` in the jobs); an owner invoice per owner-use booking, debit attempts claimed once; evidence and dispute packs are staff
  reads through the door; the owner sees their own invoice only.
- **Money idempotency.** Stripe events are claimed once (`server_webhook_event_claim`) and finished with the result or the error (a
  failure answers 500, so Stripe sends it again); the PaymentIntent is fetched again, never trusted from the event body; refunds,
  disputes and chargebacks are recorded once by the database (0132). Tips are staff payment requests settled by the same path with
  `idempotencyKey: payreq:<id>`. No R48 purpose is dropped by the webhook.
- **Rewards and referral credits.** One ledger row per `(owner, kind, ref_key)` (unique), so a credit is made once even when two runs
  race (the second rolls back); kit redemptions one open at a time (unique index).
- **Tracker ingest.** HMAC-SHA256 over `timestamp.body`, five-minute tolerance, constant-time comparison, fails closed without a
  key; replay guard 10 minutes (twice the tolerance); rate per minute; a sender that keeps failing the signature is refused before
  any HMAC or database call; the sender is `CF-Connecting-IP`.
- **Live map people.** Tables are RLS on with no browser grant; `live_people` answers Admin and Fleet with everyone, CS and Sales
  with renters at a pickup or return, anyone else nobody; a staff member is shown only while `location_state` says they share
  (policy accepted, on shift or on a job, never off duty); positions older than two hours are left out; never while viewing as.
- **Pickup identity check.** Photos go to the private `identity` bucket under a server-built key, removed again when the database
  refuses the check; JPEG or PNG from the bytes, 10 MB; reads run under the purpose `licence_read`, which the AI chain never sends to
  Gemini (`PRIVATE_PURPOSES`, tested); nothing read is logged; office staff read results by policy (Admin, CS, Fleet, Finance).
  Reviewed documents are viewed through `doc_view` (staff who review the booking, never an owner), logged, one-minute links.
- **Terms pop-up and agreements.** The version must bind the person and the SHA-256 of the text shown; the IP address and device
  are recorded; refused while viewing as someone; POST checks the Origin.
- **SEO lead capture and `cc_src`.** Every public form verifies Turnstile on the server (contact, owner program, place leads, tracker
  waitlist: the widget is on the form); the source cookie only adds tags to a stored lead, never decides anything, and the form's own
  fields win over it.
- **portal-gate.ts.** A redirect to sign in for `/admin` and `/staff` documents without a session cookie; every page keeps its own
  role and two-step check, so the gate only makes the answer a real 307.
- **Visitor-signals job.** One run at a time (advisory lock), `lock_timeout`, `skip locked`; service role only.
- **RLS on every new table.** On for all tables (the r35 catalog test); the 48 R48 tables have the admin policy, no grant to `anon`,
  and `authenticated` reads only where a policy says (staff reads of evidence, pound lots, tracker events, pickup checks).
- **Grants.** No R48 definer function is callable by `anon` or `authenticated` beyond the pinned lists (r35 test).
- **Secrets in bundles.** Browser and app see only `NEXT_PUBLIC_*` (URL, anon key, Stripe publishable key, Turnstile site key) and the
  app's site address; Firebase files are written from GitHub secrets at build time; server modules import `server-only`.
- **No PII to owners or logs.** Owner pages and emails carry the renter's name and mobile only for a Self-Managed car's own
  handover (`is_self_managed`, by design); new log lines carry ids, codes and error names.

## The 20-item checklist

| # | Item | Status |
| --- | --- | --- |
| 1 | HTTP/2 Rapid Reset | Cloudflare in front; Caddy (Go, patched since 2023) behind it; Node never terminates HTTP/2 |
| 2 | bcrypt 72 bytes | New passwords capped at 72 bytes (finding 9); identifiers have length limits in every shape (email 200, tokens 6000, ids by pattern) |
| 3 | SAML | None in the code |
| 4 | nOAuth | Google only; Supabase links a provider sign-in only on a verified email and removes unconfirmed identities (`oauth.ts`) |
| 5 | Batched calls | No GraphQL; the mobile API is one operation per request; server actions one each |
| 6 | 2FA replay | TOTP checked by Supabase Auth (challenge then verify, rate limited); texted codes single use with attempt limits (`server_signin_phone_request`) |
| 7 | ReDoS | New patterns are anchored and linear; inputs are length-capped before any pattern runs |
| 8 | JWT confusion | Algorithms pinned, `iss` now required (finding 8) |
| 9 | Request smuggling | One chain: Cloudflare, Caddy, Node; Caddy rejects ambiguous framing |
| 10 | Cache poisoning | The mobile API, `/api/terms`, the live map routes answer `no-store`; cached pages carry no user data (page cache keys only signed-out requests) |
| 11 | Spoofed IP header | `CF-Connecting-IP` only in production (finding 5) |
| 12 | Views bypass RLS | Every browser-readable view is a security barrier or invoker (r35 test); no new view is browser-readable |
| 13 | Math.random tokens | None in new code; tokens and challenges from `crypto` or `gen_random_uuid` |
| 14 | Timing | Tracker signatures, job tokens and webhook signatures compared in constant time |
| 15 | Padding oracle | No custom CBC; WebCrypto ECDSA/RSA verify and HMAC only |
| 16 | Prototype pollution | No deep merge of user JSON; the mobile shapes copy named fields only; spreads define own properties |
| 17 | Template injection | Email templates are data with escaped variables; no user input is evaluated |
| 18 | XXE | No XML parsing in R48 code |
| 19 | WebSocket hijack | No sockets; live updates poll keyed topics |
| 20 | Unicode accounts | NFKC and lower case everywhere, ASCII-only new accounts (finding 3) |

## Brand-audit patterns

| Pattern | Here |
| --- | --- |
| Public forms not sending Turnstile | Every public form sends it and the server verifies it |
| X-Forwarded-For trusted | Fixed (finding 5) |
