# The handover on one screen, and the late return is a choice (Release 42: 2710, 2711)

Branch `r42-handover`. Migrations `2710_r42_handover_late.sql` and `2711_r42_handover_late_guides.sql` (the guide
chapters, generated by `supabase/seed/2711_gen_guides.mjs`). SCHEMA_MARKER 2711. One table added
(`late_return_decisions`), so the database types are regenerated. DB test `supabase/tests/99_r42_handover_late.sql`
(and `08_booking_app.sql`, `09_operations.sql`, `82_handover_signing_licence.sql`, which now make the late return
choice where they expected the automatic line); unit tests `web/src/features/handover/late-return.test.ts` and
`web/src/features/field/one-screen.test.ts`; e2e `staff.spec.ts`, `handover-signing-licence.spec.ts` and
`field-finance-owner-mtd.spec.ts` follow the one-screen flow.

The owner: "The check-in and check-out process has to be made much easier", and a late return must not be invoiced by
itself: staff choose how it is charged.

## 1. One screen per handover

| Part | What changed |
| --- | --- |
| The checklist | `features/field/Checklist.tsx` was a wizard of 14 steps (pickup) or 10 (return), one per screen with Next and Back. It is one screen: every part on the page in the order it is done, each with a tick once complete; one button at the bottom, and above it a second one that names what is still needed and goes to it |
| Prefilled | `app.handover_defaults` (added to `field_read('job')` as `defaults`): the odometer and fuel from the Tracker when it reported in the last 30 minutes, else the car's last report; the fuel and keys of the pickup for a return; Standard cleanliness; the renter taken as present at a return. Each prefilled field says where its value came from until it is changed. A return's odometer is never prefilled lower than the pickup's |
| Fewer taps | The renter, the licence and the card are one tap each (was a Yes or No screen each). "Car ready" is no question any more: the fuel reading answers it. The ready check is one green line when everything is ready. The tracker is one line when it reports |
| Folded away | New damage, the note, belongings, "the renter is not here or will not sign", the list of all photos, the things that stop a handover |
| Saving | Answers go to the server a moment after each change (no Next to press), stay on the phone without a signal, and the screen opens where it was left |
| Same everywhere | The field job, and the check-in or check-out an Admin or an assistant opens from the booking or the To do list, are this one screen. On the booking it is the first button (**Start the check-in (pickup)**, **Start the check-out (return)**); the form with photos from the gallery (0545) is folded under it |
| The field job | **Start the check-in now** (or check-out) on a job that is not started: one tap acknowledges, starts and opens the screen. Acknowledge and Start remain |
| Not changed | What a handover requires. `complete_handover` and `complete_return` check the same photo set, readings, ID checks, deposit, tracker and signatures, and refuse anything missing |

## 2. A late return is a choice

| Part | What changed |
| --- | --- |
| No automatic charge | `app.assess_check_in` wrote the two late lines by itself at every return. It now calls `app.late_return_assess`: a return after the grace period gets a row in `late_return_decisions` (pending) and the To do **Late return: choose the charge** (Fleet); the late lines stay empty until someone chooses |
| The choices | `extension` (every started day at the booking's daily cost), `extra_days` (1 up to the started days, chosen by staff), `late_fee` (the rental terms: whole days as extra days, the started hours after them at the hourly fee, capped a day; what was automatic before), `custom` (an amount with its reason), `waive` (with the reason) |
| Where | On the return screen (sent with `complete_return` as `late_choice`; "Decide later" is the default and a choice that cannot be applied never stops the return), and on the booking's check-in and check-out card (`ops_do late_return_decide`, `ops_read late_return`) |
| The money | The choice writes the same lines as before (`late_return_extra_days`, `late_return_fee`) through `app.set_assessed_line`, so the statement, the deposit settlement (the hold, then the card on file, then a pay link) and the owner's share are unchanged |
| Audit and notice | `audit_log` (`late_return_decided`), the booking history (a new kind, `late_return_decided`), and a message to the renter on the booking in the words of the choice (emailed as every staff message is) |
| Approval | Unchanged rules: a custom amount above the person's single limit waits for an Admin; a waiver is an Admin's, Finance's or Fleet's (as `check_in_waive`), anyone else's waits for an Admin (To do **Late return: approve the charge**). Only an Admin changes a decided late return, and never once the line is on a statement or paid |
| Close ended trips | Marking a trip returned late with **Deduct the late fee** is the choice of the late return fee, made there; no renter message for a trip closed long after |
| Earlier returns | A return already charged the old way keeps its lines: recorded as decided (`late_fee`) |
| Time correction | A return corrected to inside the grace period loses its decision and its late lines |
