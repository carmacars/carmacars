# Owner new booking notice when a booking starts counting; the card that covers a rental (Release 42: 2610, 2611)

Branch `r42-fixes`. Migrations `2610_r42_fixes.sql` and `2611_r42_fixes_guides.sql` (the guide chapters, generated by
`supabase/seed/2611_gen_guides.mjs`). SCHEMA_MARKER 2611. DB test `supabase/tests/99_r42_fixes.sql`; unit tests in
`web/src/features/coverage/card.test.ts`.

| Part | What changes |
| --- | --- |
| Owner new booking notice | Release 40 (2480) leaves a booking out of its car owner's revenue and view when it is an insurer rental that does not block the calendar, an insurance replacement hidden from the owner, or has "Counts toward the owner's revenue" off, and the 0156 trigger drops its owner booking notices. When staff later make it count (Blocks the calendar on, shown to the owner, billed to the renter, "Counts toward the owner's revenue" on), the owner now gets `owner_new_booking` once. One trigger on `bookings` (`bookings_owner_counts_flip`, `app.owner_counts_flip_notice`) watches `app.booking_counts_for_owner` go from false to true, so every place that changes `blocks_calendar`, `owner_visibility`, `owner_revenue_excluded`, `bill_to` or the status is covered |
| Never twice | Event key `owner_new_booking:<booking>:counted`; nothing is sent when the owner already had the notice (an earlier one not dropped by 0156) or has one waiting, when the owner still sees the booking as unavailable, for an Owner Booking, or for a booking that is pending or cancelled (the normal confirmation notice covers a pending one). The booking's history records that the notice was sent |
| Pay page notice | When the booking uses credit card coverage and the covering card's network is known, the pay page says "Pay with the card that covers this rental (Visa)" (`public.server_coverage_card_network`, returned with `startPayment`) |
| Different network, before charging | The pay page stops a card of another network before it is charged when the browser knows the brand (the fake adapter from the number's digits; Stripe through `createPaymentMethod` on the Payment Element, skipped when Stripe cannot tell) |
| Different network, server | `app.record_booking_payment` (wrapped `_pre2610`) refuses with `card_network_mismatch` and "Pay with the card that covers this rental (Visa). The card you used is a Mastercard card, so the booking was not confirmed. Nothing was charged." before anything is recorded; the authorization is voided as for every refusal. Unknown brands are not refused here (the same-card check of 0203 and the coverage confirmation still decide) |
| Guides | The owner and admin guides said the statement includes every booking; they now state the release 40 rule |

Offer approval still does not re-ask for the card coverage ticks (noted in release 40); not changed here.

## Guides

- `owner/bookings-and-your-own-use`: what the statement leaves out, and the new booking email when a booking starts counting
- `owner/fees-payments-and-payouts`: the statement lists the bookings that count toward the owner's revenue
- `admin/requests-offers-and-bookings`: the release 40 rule in full, and the owner notice when a booking starts counting
- `renter/sign-and-pay`: paying with the card that covers the rental
