# AI search: robots, llms.txt, the facts page and the short answer

The owner, October 23, 2026: every AI answer engine (ChatGPT search, Claude, Perplexity, Gemini and Google AI Overviews,
Copilot and Bing, Meta AI, Apple, DuckDuckGo, Brave, You.com) and every search engine should find, understand, cite and
recommend carmacars.ca. Branch `geo`, from `formfill2`. No migration: everything reads what the database already holds.

## 1. robots.txt names the crawlers

- `web/src/features/seo/crawlers.ts`: the crawlers named, by the token each company publishes (October 2026): the search
  engines (Googlebot, Bingbot, DuckDuckBot, Applebot, YandexBot, Yeti, SeznamBot, Baiduspider), OpenAI (OAI-SearchBot,
  ChatGPT-User, GPTBot), Anthropic (Claude-SearchBot, Claude-User, ClaudeBot), Perplexity (PerplexityBot,
  Perplexity-User), Google (Google-Extended, Google-CloudVertexBot, Gemini-Deep-Research, GoogleOther), Apple
  (Applebot-Extended), Meta (Meta-ExternalAgent, Meta-ExternalFetcher, Meta-WebIndexer, FacebookBot), Amazon (Amazonbot,
  Amzn-SearchBot, Amzn-User), DuckAssistBot, MistralAI-User, YandexAdditional, cohere-ai and CCBot. Copilot and ChatGPT
  search also read Bing's index; Brave and You.com publish no token of their own and fall under `*`.
- `web/src/app/robots.ts`: one group for the named crawlers and one for `*`, with the same private paths (a crawler that
  finds its name ignores the `*` group). `/auth/` joins the private paths. The sitemaps are listed as before.
- The Worker entry, the app and the edge cache never refuse a crawler: the only user agent check (`isBot`,
  `src/lib/track/shared.ts`) keeps bots out of the live visitor counts and still answers them.
- Cloudflare's own settings can override robots.txt ("Block AI bots", the managed robots.txt, Bot Fight Mode, AI Crawl
  Control). They could not be read from this workspace (the proxy refuses carmacars.ca and the API token lives in CI).
  `scripts/deploy/cloudflare.sh crawlers` (read only) now reports them on each production deploy, with what the live
  site answers OAI-SearchBot, ClaudeBot, PerplexityBot and GPTBot, and warns with the dashboard steps when anything blocks.

## 2. /llms.txt and /llms-full.txt

- `web/src/features/seo/facts.ts` reads the entity facts from the database: site settings (name, address, phone,
  hours, area), program settings (ages, licences, booking length, deposits, cancellation, HST), the real cars (sample
  cars never set a price: classes with their count and lowest daily rate, the weekly and 30-day lows, the lowest
  delivery fee), the chauffeur rates, the indexable landing pages, the guides and the home page questions.
- `web/src/features/seo/llms.ts` (pure, unit tested) writes `/llms.txt` (llmstxt.org: the name, a one sentence summary,
  the key facts, the services, the places, the policies, the guides) and `/llms-full.txt` (every fact and every question
  in Markdown). Served as text/plain, rebuilt at most hourly, `noindex` for search results.
- "Facts updated" is the latest real change: a real car, an indexable landing page or a guide. Without one, no date.

## 3. Structured data

- The business node (AutoRental, `#business`) is now on every page from the layout, from settings only (`lite`: no
  price range, places or rating), so every reference to it resolves: the WebSite's publisher, a Service's provider, a
  car's seller, a guide's publisher. Home, contact, the location landing pages and /about add the price range of the
  real cars and the places served to the same node.
- The node gains `contactPoint` (customer service, the phone and email, English) and `hasMap` when the Google place id
  is set. `sameAs` stays the social profiles and the Google listing.
- Guides reference `#business` instead of a second node with the same id and another type.
- The mechanical work we arrange (0121) never carries a Service node, even if a shop service is attached later (it
  already had no questions and no prices).
- /about: AboutPage, BreadcrumbList, the full business node.
- Already in place and checked: BreadcrumbList on every public page but home, FAQPage only where the page shows the
  questions, Product and Car with real specs on the car pages, Offers only from real rates, ratings only from published
  reviews shown on the page, WebSite with its SearchAction.

## 4. The short answer and the facts page

- `web/src/components/AnswerBlock.tsx`: one sentence (who, what, where, the price from, how to book), the facts as
  rows, and "Updated" with a real date when there is one. On home, /car-rental, every landing page (its own last
  change), /chauffeur, /delivery (the real cars' last change), /detailing, /body-shop and /about.
- `/about` (new, in the pages sitemap and the footer): name, address and phone, area, fleet and prices by class,
  renting rules, services and places, and a link to `/llms-full.txt`.

## 5. Bing and IndexNow

Already in place, checked: the IndexNow key file answers at `/<key>.txt` (next.config.ts rewrite to
`/api/site-file`), the key goes to Bing's endpoint, which shares every submission with the other IndexNow engines
(Yandex, Naver, Seznam, Yep), and Admin > Settings > Site has "Bing site verification" (the `msvalidate.01` meta).
