# SES bounces and complaints, Realtime switched on (Release 42: 2630)

Branch `r42-ses-bounce`. Migration `2630_r42_ses_events.sql` (`public.server_outbox_record_bounce`, a server-only wrapper of
`app.outbox_record_bounce`; no table, column or suppression reason added). Tests: `supabase/tests/99_r42_ses_events.sql`,
`web/src/lib/ses-sns.test.ts` (signatures checked against a throwaway certificate and key made with openssl at test time).
Setup: `docs/email-providers.md`.

| Part | What changed |
| --- | --- |
| Endpoint | `POST /api/ses/events` (`web/src/app/api/ses/events/route.ts`, `web/src/lib/ses-sns.ts`) takes Amazon SNS messages. The signature is checked on every one (SignatureVersion 1 = SHA-1, 2 = SHA-256, Web Crypto): the certificate is fetched only from `https://sns.<region>.amazonaws.com/` (a `.pem`, no redirect, default port), must name SNS and be in date, and the signed string is rebuilt from the fields AWS lists for the type. A failed check is a 403 and nothing is read |
| Subscription | A `SubscriptionConfirmation` is confirmed by fetching its `SubscribeURL` (same host rule), so adding the URL to the SNS topic is the whole setup |
| Suppression | A Permanent bounce or a Complaint puts each address in Blocked addresses (`email_suppressions`, scope all, reason bounce or complaint, the same as the existing bounce handling): never emailed again, the email's row is failed, what still waits for it is not sent, and a booking email to a renter raises the confirm-the-address task. Transient and Undetermined bounces are ignored. Repeats add nothing |
| Safety | A validly signed message can come from anyone's SNS topic, so the database wrapper acts only on a message id we sent (`ses:<id>` in the outbox) and an address that email went to |
| Realtime | The deploy in `ci.yml` never runs Docker Compose on the server; the `vps-provision` workflow does (`stack-up`). `infra/vps/scripts/make-env.sh` now keeps `COMPOSE_PROFILES` and adds `realtime` when missing, after checking the pinned image exists in the registry; the repository variable `REALTIME_ENABLED` (default true) turns this off. It takes effect on the next run of vps-provision (it also stopped `make-env.sh` from dropping a hand-added line). `infra/vps/CUTOVER.md` has the steps |

## Guides

No guide change: the endpoint and the server switch have no screen; Blocked addresses already lists a bounced or complaining address.
