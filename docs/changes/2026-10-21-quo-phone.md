## 1. How it fits together

```
Quo (call or text on the CarmaCars number)
  -> webhook POST https://carmacars.ca/api/webhooks/quo     signed (Standard Webhooks: webhook-id, webhook-timestamp,
                                                            webhook-signature; the legacy openphone-signature too)
  -> web/src/features/phone/webhook.ts                      signature checked on the raw body (5-minute tolerance), payload read
  -> public.server_phone_event                              thread for the number, matching, the call or text, opt-outs,
                                                            the missed-call rule; answers the texts to send now
  -> web/src/integrations/phone (Quo API POST /v1/messages) a text from the CarmaCars number
Booking emails (notification_outbox) -> trigger -> phone_outbox -> five-minute cron tick (server_jobs_due "phone")
  -> /api/jobs/phone -> Quo
Staff: Live chat > Texts and calls -> /api/staff/phone -> the door (Admins, customer service, Sales) -> Quo
```

| Piece | Where |
| --- | --- |
| Signature check and payload reader (no imports; current and legacy shapes) | `web/src/features/phone/webhook.ts` |
| Quo API client (send a text, numbers, webhooks: list, create, update, rotate, `ensureWebhook`) | `web/src/features/phone/quo-api.ts` |
| Templates (the database's rules, for previews and tests) | `web/src/features/phone/templates.ts` |
| Sample deliveries (Quo's documented payloads) | `web/src/features/phone/samples.ts` |
| The line (real: Quo; fake: records, for local work and tests) | `web/src/integrations/phone/` (`QUO_PROVIDER`, `QUO_API_KEY`, `QUO_API_BASE`, `QUO_WEBHOOK_SECRET`) |
| Server side: webhook, sending, the job, staff reply and AI suggestion | `web/src/server/phone.ts`, `web/src/app/api/webhooks/quo`, `api/jobs/phone`, `api/staff/phone` |
| Inbox, calls on records | `web/src/features/phone/PhoneInbox.tsx`, `PhoneTimeline.tsx`, `client.tsx`, `InboxTabs.tsx` |

## 2. Features (all in Program settings, "Phone and texts (Quo)"; on by default unless noted)

| Feature | What happens |
| --- | --- |
| Record every call and text | Events received: `message.received`, `message.delivered`, `message.failed`, `message.undelivered`, `call.ringing`, `call.answered`, `call.completed`, `call.missed`, `call.forwarded`, `call.recording.completed`, `call.summary.completed`, `call.transcript.completed`, `call.voicemail.completed`. One `phone_threads` row per outside number, one `phone_activity` row per call or text (updated by later events of the same call). A delivery Quo retries is applied once (`phone_webhook_log`, 3 days). Another Quo number of the workspace is ignored (`quo_config.phone_number_id`, set by the deploy) |
| Matching | By the number in E.164: staff (users with a staff role), then a renter (their mobile, or the account holder's), with their current booking (on rent, else the next one, else the latest), then an owner (or partner), then a lead (a lead, a discount game claim, a live chat that gave this phone). Shown on the booking's History tab, the renter page and the owner page ("Calls and texts"), and in the inbox. A number nobody has is an **Unknown caller**: **Create lead** (a `phone` lead) or **Link to** a renter (audit log). A link made by hand stays until **Match automatically again** |
| Missed call | A task "Missed call from ..." (`phone_missed_call`, high, 15 opening minutes; one open task per number) to the person on duty in `phone_missed_call_queue` (customer service by default: whoever has Live chat or Texts and calls open within `chat_shift_minutes`), otherwise that queue, and the Admins' queue when nobody holds the function. In the site check's quiet hours (23:00 to 07:00) it is due when they end. Not for staff calling in |
| Missed-call text | **Off by default** (owner's choice of October 21: Quo's own missed-call auto-reply is used). When switched on: the template `phone_missed_call_text` ("Sorry we missed your call. How can we help? Reply here, or book at carmacars.ca. CarmaCars"), sent at once from the webhook answer, at most once per number per `phone_missed_call_text_hours` (12), never to staff or a number that opted out. Admin note: "Turn off Quo's own missed-call auto-reply first, or callers get two texts" |
| Texts in the inbox | Admin > Bookings > Live chat > **Texts and calls**, and the assistants' Live chat (customer service and Sales): numbers by last activity, unread and missed counts, the thread, **Send text** (Quo, from the CarmaCars number), **Suggest a reply** (an AI draft put in the box, never sent by itself), **Stop texts**, **Call** (tel: link), who the number is with their bookings, and their visit on the site |
| AI | Workers AI through the existing LLM integration (the usage guard of branch `assistant` is not on main): suggestions and one-line call summaries within `phone_ai_daily_neurons` (1,500) and the all-use cap `chat_ai_total_daily_neurons`; every call is a `provider_calls` row (`phone_draft`, `phone_summary`). A suggestion naming a price or coverage is dropped |
| Booking texts | One text for each of these renter emails: offer sent (`renter_offer_ready`), booking confirmed (`renter_booking_confirmed`), payment received (`renter_payment_receipt`), pickup tomorrow (`renter_booking_reminder`), return reminder (`renter_return_reminder`), payment link (`renter_recovery_pay`). Only transactional emails, to renters with a mobile number, not opted out; each moment on or off with its text; held until the quiet hours end; the first text to a number ends "Reply STOP to opt out." Sent by the five-minute job; a temporary failure is tried again (3 times), a refusal (A2P not approved, bad number) fails at once |
| STOP and START | STOP (and STOPALL, UNSUBSCRIBE, CANCEL, END, QUIT, ARRET) stops texts to the number and sets `renters.sms_opt_out_at`; queued texts are skipped. START (UNSTOP, YES) allows them again. Quo and the carriers also block on their side. A carrier error for a landline or blocked number (21610, 30004, 30005, 30006) stops texts to it |
| Summaries and transcripts | Quo's summary and next steps, the transcript, recordings and voicemail (with its transcript) are kept on the call. With a transcript but no Quo summary, a one-line AI summary follows within about 5 minutes. **Recording is off on the line** (owner's choice), so there are no transcripts or Quo summaries for now: calls show their length and voicemail, and no empty transcript or recording section is shown |
| Live visitors | A caller or texter who gave the same phone in live chat or a discount game is linked to their browser: the thread shows their visit (pages, current page) and Live visitors shows their name |
| Retention | Calls and texts linked to a renter, owner or booking stay with the rental records; the others are deleted after `phone_keep_months` (12), daily (pg_cron `carmacars-phone-housekeeping`, 08:41 UTC) |

Templates: 1 to 480 characters, no long dashes, must name CarmaCars (database check
`program_settings_phone_texts_check`); placeholders `{first_name}`, `{booking}`, `{car}`, `{pickup}`, `{return}`,
`{amount}`, `{link}` (the renter's booking page).

## 3. The webhook: how it is registered

`scripts/deploy/supabase.sh quo` (deploy job step "The Quo phone line", production only, `continue-on-error`) runs
`scripts/deploy/quo.mjs setup`:

1. The key: the repository secret `QUO_API_KEY` (then copied to the vault as `deploy_quo_api_key`), or the vault's copy.
   No key: a notice, nothing else.
2. `GET /v1/phone-numbers`: the inbox whose number equals Site settings, phone (`app.phone_our_number()`); its id goes in
   `quo_config.phone_number_id`.
3. `GET /webhooks` (`Quo-Api-Version: 2026-03-30`): ours is the one whose URL is `https://carmacars.ca/api/webhooks/quo`.
   None: `POST /webhooks` with the 13 events and `resourceIds` [that inbox]; Quo answers the signing key once
   (`whsec_...`). Found: events, number and status refreshed with `PATCH` when they differ. Found but the vault has no
   key: `POST /webhooks/{id}/rotate`. Never a second webhook.
4. A new key goes to the vault (`deploy_quo_webhook_secret`) through a file of mode 600, never printed; the step exports
   `QUO_API_KEY` and `QUO_WEBHOOK_SECRET`, which "Deploy the Worker" adds to the Worker's secrets file (the same jq list as
   `STRIPE_WEBHOOK_SECRET`). The build sets `QUO_PROVIDER=quo`.

`.github/workflows/quo-check.yml` (Run workflow, read only): checks the key and prints the workspace's numbers (name
and number) and webhooks (address, status, number of events).

API base: `https://api.openphone.com` (the address given for this work); Quo's documentation now names
`https://api.quo.com` for the same API. `QUO_API_BASE` switches it; quo-check shows whether the key works at the base.
