# Sorting on every list, one hiring pipeline, onboarding approval in sight (Release 43)

Branch `r43-ux`. No migration. Unit tests: `web/src/lib/sort.test.ts`, `web/src/features/staff-onboarding/pipeline.test.ts`;
e2e `web/tests/e2e/r43-ux.spec.ts`.

The owner's reports: lists could not be sorted by recentness; onboarding approval could not be reached from its alert; the hiring
and onboarding area was unorganised.

## What changed

| Part | What changed |
| --- | --- |
| Sort | `web/src/lib/sort.ts` (pure): `?sort=newest|oldest|active|az`, only in the address. The shared `Table` (`features/admin/ui.tsx`) shows a sort select for any list that has a date, reorders its rows in the browser (`SortTable.tsx`), and takes `defaultSort="newest"` for people lists. Lists ordered in SQL (Renters, Bookings) order by the sort in the query (`sqlOrder`); Owners sorts its list. Admin and staff share the same pages and the same `Table` |
| Approval in sight | `Waiting for your approval` with Approve and Reject at the top of `/admin/settings/staff` (the alert's page, anchor `#onboarding-approvals`), as a card on Admin Today, and an `Approve onboarding` button on the person's row on Staff and roles. The Fleet page shows the same component |
| Hiring pipeline | `/admin/hiring?tab=stages` (`features/staff-onboarding/Pipeline.tsx`, stages in `pipeline.ts`): Applied, AI interview, Interview booked, Decision, Hired: agreement to sign, Academy, WhatsApp groups, Waiting for approval, Onboarded; each person in exactly one stage with the one next action and a count per stage. The Staff onboarding block left Settings; Staff agreements stays there |

## Guides

No guide change: the chapters for the sort and the pipeline are written in the guide pass of the release.
