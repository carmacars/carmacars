## B3. API access and the Claude connector

- 0562: `api_keys` (the SHA-256 of each secret only, scopes, revocable), `api_oauth_clients`, `api_oauth_codes`,
  `api_calls` (append-only: who, tool, record, before, after, outcome). `app.api_call` checks the key, the scope, that its
  person is still an active Admin and the rate limit (Program settings `api_calls_per_minute`, 60), runs the tool as that
  person (`door_begin`: the audit log and every guard trigger see them) and logs it. Tools: whoami, list_bookings,
  get_booking, update_booking, list_requests, update_request (a request before its offer), list_owners, get_owner,
  update_owner; each update changes only its listed fields (`features/api-access/tools.ts`), never prices, payments or status.
- `/api/mcp`: the MCP server (JSON-RPC over POST). OAuth 2.1 for Claude: `/.well-known/oauth-protected-resource` and
  `/.well-known/oauth-authorization-server` (rewrites), Dynamic Client Registration (`/api/oauth/register`: Claude's
  callback and loopback addresses only), the consent page `/oauth/authorize` (Admins only, scopes to tick), the token
  endpoint (PKCE S256, one-hour access tokens, 30-day rotating refresh tokens).
- Admin > Settings > API access: the setup steps, Make a key (shown once), the keys and connections with Revoke, the call log.
