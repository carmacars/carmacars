# Amazon SES as the first email sender (Release 41: 2570)

Branch `r41-ses`. Migration `2570_r41_ses.sql` (new Program settings `email_ses_enabled`, `email_ses_daily_max` and `email_ses_marketing`; new
columns on `email_provider_state`; new `app.ses_emails_between`, `app.ses_email_left`, `app.ses_email_try`,
`public.server_ses_email_result`, `public.server_outbox_note_ses_fallback`; wraps `app.email_day_cap` and `app.email_pace` as
`_pre2570`; patches the claim, Resend's counts and `app.outbox_mark_sent_pre0900` in place; publishes the guide chapter below).
No applied migration is edited. Tests: `supabase/tests/99_r41_ses.sql`, `web/src/lib/email-ses.test.ts` (AWS's published
SigV4 test vectors, the MIME email, the error classes, the provider order). Setup and costs: `docs/email-providers.md`.

The owner: Amazon SES (ca-central-1) as the main sender once live (cheap, high volume), Cloudflare Email and Resend kept as
fallback. SES is paid per use; the owner approved it, the one exception to "never on a paid plan", held at a daily maximum.

| Part | What changed |
| --- | --- |
| Sender | `send-outbox` tries SES first: SES v2 SendEmail over HTTPS, signed with SigV4 written by hand (Web Crypto, no AWS SDK, no new dependency: `web/src/lib/email-ses.ts`, copied next to the function as `ses.ts`). Raw MIME content keeps the HTML and text, Reply-To, attachments, List-Unsubscribe and List-Unsubscribe-Post. Secrets `AWS_SES_ACCESS_KEY_ID`, `AWS_SES_SECRET_ACCESS_KEY`, `AWS_SES_REGION` (default ca-central-1), optional `AWS_SES_CONFIGURATION_SET`; without the keys SES is skipped and nothing changes |
| Marketing | Never through SES (the owner: SES production access is requested as transactional; AWS wants recipients who asked). `email_ses_marketing` (off) changes it. With it off the marketing allowance is the free capacity less only the part of the reserve SES's day does not cover (`app.marketing_daily_max` wrapped as `_pre2570`) |
| Errors | Throttling: the email waits a minute (attempts untouched). `MessageRejected` (a sandbox recipient not verified): Cloudflare or Resend sends that email. Any other refusal: the same, and SES rests 15 minutes |
| Order and capacity | SES first while `email_ses_enabled` (on) and today's SES sends are under `email_ses_daily_max` (200 in the sandbox), then Cloudflare, then Resend's free plan. The day's capacity (`app.email_day_cap`) adds SES's day; the marketing allowance of 2520 counts SES's cap only with `email_ses_marketing` on (see Marketing). SES sends never count as Resend's |
| Admin | Settings > Program settings, Email and notifications: the three SES settings. Settings > Logs > Emails: a Sent by column (Amazon SES, Cloudflare or Resend); the Why column says when an email went elsewhere after an SES refusal |
| Deploy | `.github/workflows/ci.yml` passes `secrets.AWS_SES_ACCESS_KEY_ID`, `secrets.AWS_SES_SECRET_ACCESS_KEY` and the variables `AWS_SES_REGION`, `AWS_SES_CONFIGURATION_SET`; `scripts/deploy/supabase.sh` sets them as the function's secrets only when both keys are set |
