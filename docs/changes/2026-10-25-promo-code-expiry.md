# Promo codes expire, and people are told before they do, October 25, 2026

The owner's request: "Make discount codes received from games and other ways expire and make sure that you are notifying
people of the upcoming expiry of the discount code."

Migration `supabase/migrations/0161_promo_code_expiry.sql` (SCHEMA_MARKER `0161`), its catalogue block generated by
`supabase/seed/0161_gen_catalogue.mjs` and its guides block by `supabase/seed/0161_gen_guides.mjs`. Test:
`supabase/tests/99_promo_expiry.sql`.

## 1. Every code for a person has an end date

A *personal* code is a code issued to a person: a discount game code (`source = 'discount_game'`), a come-back code
(`followup_7d`, `followup_30d`), a Live visitors code (`live_visitors`) or any code made for one renter (`renter_id` set).
I found these ways of issuing a code, and each already set an end date; the migration makes that a rule of the table:

| Source | Where it is made | Lasts (setting) |
| --- | --- | --- |
| Discount game | `app.server_game_claim` (0069, 0081) | `game_code_valid_days`, 7 |
| Come-back, 1 week and 1 month | `app.notify_followups` (0023) | `notify_comeback_valid_days`, 30 |
| Live visitors discount | `app.live_action` `live_discount` (0086) | `visitor_signal_config.discount_valid_days`, 3 |
| Made for one renter (staff, Admin > Promo codes, any other personal code) | `app.admin_save` (0030) | new `promo_default_valid_days`, 30 |

There is no code made by the chat assistant or by a referral: `referral_code` on staff and owners is a kickback, not a
discount, and no function other than the four above inserts into `promo_codes`.

- A trigger (`promo_codes_expiry_guard`) gives a personal code inserted without an end date its source's days, and refuses
  to take the end date away later ("A code issued to a person needs an end date").
- The backfill: every personal code on file without an end date got `now() + promo_default_valid_days` (30 days from the
  migration, never in the past).
- A public code (no renter, a campaign source) may still have no end date: an Admin empties **Valid until**. The Add form
  in Admin > Settings > Promo codes now starts with an end date 30 days ahead and says so.

## 2. Expired codes are refused

`app.promo_code_problem` ("This code has expired", 0016) is the one check behind every place a code is typed: the quote and
the booking form (`public.my_promo_code_problem`, `public.quote_booking`), the request (`app.request_booking`,
`app.submit_booking_request`), the offer (`app.apply_promo_code`), Add a rental (`app.manual_rental_create`) and the Admin
booking edit (`app.admin_apply_booking_edit`). That already held; the new suite tests each door. A code already on a booking
request is reserved for it (the redemption is `applied`), so a booking whose price was set while the code was good keeps it.
The only change is the wording in the request form, which no longer says an ended code "stays yours until it expires".

## 3. Reminders

For every personal code that is not used: **one 3 days before its last day and one the day before**, on by default.

| Setting (Admin > Settings > Promo codes) | Default |
| --- | --- |
| `promo_reminders_enabled` | on |
| `promo_reminder_3d_days` (0 turns it off, else 2 to 30) | 3 |
| `promo_reminder_1d_on` | on |
| `promo_default_valid_days` | 30 |

"Last day" is the Toronto day on which the code's last moment falls (a code that ends at midnight ends the day before). A
reminder is due from the start of its day: the first on the day `promo_reminder_3d_days` before the last day until the day
before the last day begins, the second on the day before the last day until the code ends. A code made after the day a
reminder opens gets no reminder of that kind (a Live visitors code, valid 3 days, gets the day-before reminder only).

| Email (and its text) | Class | For |
| --- | --- | --- |
| `renter_promo_expiry_3d`, `renter_promo_expiry_1d` | marketing, express consent | come-back, Live visitors and renter codes |
| `renter_game_code_reminder_3d` (new) | transactional | game codes |
| `renter_game_code_reminder` (0069, now the day-before reminder) | transactional (unchanged) | game codes |

Each has the code, what it gives, the end date and the book link (`/cars`), and a text template in Admin > Text alerts.

- **Channels and consent.** The emails go through the existing pipeline, so the person's channel (Email, Text or Both),
  the verified phone, STOP, the outbox's sending hours (marketing 9 am to 9 pm), the text quiet hours (9 pm to 8 am) and its
  daily limits all apply. A reminder of a code made for a renter is an offer: it is not sent without express consent,
  never to an unsubscribed or blocked renter (the job does not even record it), and the outbox refuses it again (suppression and
  consent rule). A game code reminder is the reminder of a code the visitor asked for and goes either way, as before.
- **Never twice.** `promo_reminders` holds one row per code and kind (unique). The reminders sent by 0069 were copied in as
  the day-before reminder, and the game's event key is unchanged, so the old and the new path cannot both send.
- **Never after use or the end.** A code on a booking request or redeemed gets no reminder; a reminder waiting in the
  outbox (email or text) when the code is put on a request is cancelled, and one waiting when the code ends is cancelled by
  the job.
- A Live visitors code given to a visitor we cannot identify has nobody to remind: it was handed over in the chat.

## 4. The job

`app.job_game_reminders` (pg_cron `carmacars-game-reminders`, every 30 minutes, 0069) now calls
`app.promo_reminders_run` before its housekeeping. No new job, no change to the Worker.

## 5. Where it shows

- **Admin > Settings > Promo codes**: each code with its end date and reminders sent (first, day before), the rules card
  (the settings above, with the games' and come-back days), and "Codes sent to people" (games, come-back, Live visitors:
  code, source, end date, state, reminders sent). `app.admin_settings` returns `promo_codes`, `promo_personal` and
  `promo_personal_count`.
- **The renter's account (Your trips)**: "Your discount codes" with what each gives, its last day and the days left
  (`public.server_my_promo_codes`); a code ended in the last 14 days shows as ended.
- `game_reminder_hours` stays in the table but is no longer read (its Admin field is removed from Discount games).
